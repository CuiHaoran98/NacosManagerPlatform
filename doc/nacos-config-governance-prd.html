TongNCS 配置治理平台（NCG）

在现有 TongNCS 之上增加变更审批、发布管控、全量审计与影响面提示。TongNCS 继续作为配置内容的唯一事实源，平台不替换、不改造 TongNCS，也不引入第二套配置存储。

说明：TongNCS 是公司在用的配置平台，使用体验与 Nacos 趋同；本文沿用的 Namespace / Group / DataId、Beta / Tag 灰度等术语，均指 TongNCS 的对应能力。

版本 v1.1 日期 2026-11-21 范围 P0 · 12 项功能 底层存储：现有 TongNCS 生产单人会签 审计永久保留
01

产品契约

先固定"为谁、在什么时刻、完成什么、什么算完成、凭什么信任"，后续功能都由此推导。

主要用户 已经在使用 TongNCS 的研发团队：应用负责人、配置编辑者、发布者、审批人、审计员。他们已有 TongNCS，痛点不是"没有配置中心"，而是"缺少变更治理"。
触发时刻 需要修改生产配置；需要向审计/合规证明"谁在何时改了什么"；需要阻止未经审批的配置进入生产；需要快速回滚；需要在多个环境之间安全地搬运配置。
核心任务 把"直接改 TongNCS"变成"发起变更单 → 审批 → 受控发布 → 读回校验 → 全程审计 → 可回滚"的闭环，同时保持 TongNCS 仍是运行时读取配置的唯一来源。
完成条件 一次配置变更从提出到生效，全过程可追溯、可举证；未经平台发布的直连 TongNCS 变更能被发现并报警；生产变更由提交人以外的一名审批人单人会签把关；失败可安全回滚，误删可在 30 天内恢复。
信任基础 ① 生效配置只存在于 TongNCS，平台草稿与快照不作为运行时来源；② 每次写入都读回校验；③ 审计只追加、不可修改、可导出校验；④ 权限判断失败时默认拒绝。
一句话定位：NCG 是 TongNCS 的"治理层"，不是"替代品"。TongNCS 负责存配置、推配置；NCG 负责谁能改、怎么审、何时发、发了什么、出问题怎么退。
02

背景与问题

TongNCS 的配置中心能力已经覆盖"存、推、灰度、版本"，缺的是围绕变更的组织级控制。

已有
Namespace / Group / DataId 配置模型、历史版本与回滚、Beta/Tag 灰度、基础 RBAC；dev / staging / prod 为独立实例部署
缺失
审批流、编辑与发布强制分离、全量操作审计、应用-环境语义、变更单与影响面
风险
直连 TongNCS 的改动无法被治理；TongNCS 自身历史保留有限，需平台长期留存证据；事故复盘缺少完整证据链

2.1 现状能力与缺口

能力域TongNCS 现状本平台要补齐的部分
配置存储Namespace / Group / DataId 三级坐标不改存储模型，只在上层建立"应用 / 环境 / 逻辑配置名"的映射
版本与回滚有配置历史与回滚把回滚纳入变更单与审计；区分"回上一版"和"回更早版本"的风险等级
灰度支持 Beta / Tag 灰度把灰度范围、观察窗口、放量与回滚动作记录为可审计的发布过程
权限基于命名空间与数据 ID 的读写删增加"应用 × 环境"业务语义权限，以及审批、发布、审计导出等治理权限点
审计有配置变更历史，但不是覆盖登录、授权、发布、导出的全量审计建立只追加的全量审计中心，覆盖平台内所有关键动作与直连变更检测
变更流程编辑后直接发布变更单 + Diff + 影响面 + 审批 + 计划发布 + 发布记录
可观测可查监听者把订阅实例数、受影响应用转为发布前的决策信息

2.2 典型事故路径（本产品要阻断的）

  1. 无审批直改生产：某同学为快速修复问题，直接在 TongNCS 控制台改生产配置，没有第二人知晓；出事后无法还原"为什么改、谁同意"。→ FR-03、FR-05
  2. 基于过期内容编辑：变更单编辑期间他人已发布新版本，发布时覆盖了对方的改动。→ FR-02 基线校验
  3. 不知道影响谁：改了一个看似无关的开关，导致大量实例行为变化。→ FR-07 影响面
  4. 发布结果不确定：客户端提示超时，但配置实际已写入；重复发布造成二次抖动。→ FR-04 幂等与读回校验
  5. 审计断档：需要举证时发现只有 30 天历史，且没有导出与校验手段。→ FR-05 审计保留与导出
03

范围与边界

P0 只做"让一次生产配置变更可被治理"的最小闭环，其余进入 P1。

P0 包含

  • FR-01 配置目录与详情
  • FR-02 变更单与 Diff
  • FR-03 审批中心
  • FR-04 发布与灰度
  • FR-05 全量操作审计
  • FR-06 权限与授权
  • FR-07 影响面与风险提示
  • FR-08 回滚
  • FR-09 通知与集成
  • FR-10 平台设置与 TongNCS 连接
  • FR-11 多环境对比与受控同步
  • FR-12 定时发布与批量变更单

明确不做

  • 不替换 TongNCS，不实现第二套配置存储
  • 不修改 TongNCS 内核，不要求升级到特定商业版本
  • 不做服务发现、注册中心治理
  • 不做 CI/CD 流水线、镜像发布
  • 不做通用工单/ITSM 系统
  • 不自建 KMS，密钥托管走既有安全设施
  • 多环境同步为单向受控同步：从源环境生成目标环境变更单，不做双向自动回写
  • 不提供紧急发布通道，也不接入 SSO
  • 不做多租户隔离：平台为公司团队内部使用，默认单租户
存储边界：平台只持久化"治理元数据"——变更单、审批任务、发布记录、审计事件、授权关系、配置映射与草稿。配置的生效值永远以 TongNCS 为准；平台不得把自身数据库当作运行时配置源。
04

用户与角色

角色可叠加，但同一个变更单上强制职责分离。

角色职责典型操作
平台管理员维护 TongNCS 连接、配置映射、全局策略与通知渠道接入 TongNCS、配置映射、设定审批策略
应用负责人对某应用在生产的行为负责，可授权，是高危变更的固定审批人审批高风险变更、分配角色、处理直连告警
配置编辑者编写变更内容并提交审批创建变更单、编辑草稿、查看 Diff
发布者把已审批的变更写入 TongNCS执行发布、灰度放量、回滚上一版
审批人对变更内容与影响面做独立判断通过、驳回、转交
审计员查询与导出审计证据，不参与变更检索审计、导出报表、核对哈希链
只读观察者查看配置与治理状态，不可编辑浏览目录、查看发布记录

05

核心对象与状态

对象模型决定权限、审计与状态的挂载点，必须先固定。

5.1 对象定义

对象说明关键字段
应用治理的业务单元，一个应用可包含多个配置应用标识、名称、负责人、负责人组
环境dev / staging / prod 等逻辑环境环境标识、对应 TongNCS 实例与命名空间、风险等级
配置一个具体的 TongNCS 配置项逻辑名、TongNCS 坐标（命名空间/分组/数据 ID）、格式、敏感性、当前 MD5
变更单一次受控变更的载体单号、标题、原因、变更前后内容、基线 MD5、风险等级、状态、关联发布
审批任务分配给审批人的决策单元审批人、结论、意见、处理时间
发布记录一次真实写入 TongNCS 的结果版本号、操作人、时间、目标 MD5、读回结果、灰度范围
灰度计划灰度发布的范围与节奏灰度方式、匹配条件、观察窗口、放量记录
定时任务计划到点自动执行的发布任务变更单、执行时间、执行状态、执行结果

审计事件不可变的操作证据事件 ID、时间、操作人、动作、对象、前后值、结果、来源 IP、TraceId、哈希
授权用户/组在应用与环境上的权限主体、应用、环境、权限点、有效期
订阅快照某时刻订阅该配置的实例集合采集时间、实例数、应用分布

5.2 变更单状态机

草稿→ 待审批→ 审批中→ 已通过待发布→ 发布中→ 已发布
分支状态： 已驳回 发布失败 已回滚 已取消 已过期

状态只能由系统按规则推进，不允许手工改状态。任何状态变化都写入审计。已驳回、已取消、已过期为终态；已发布仍可被回滚。

5.3 状态迁移规则

当前状态动作目标状态触发条件 / 约束

待审批审批人接单审批中审批人具备该应用/环境权限
审批中审批人通过已通过待发布生产为单人会签，1 名审批人通过即可；审批期间基线未变化
审批中审批人驳回已驳回必须填写驳回理由

06

核心流程

五条流程覆盖正常、计划发布、绕行检测、回退恢复与失败重试。

6.1 标准变更

  1. 配置编辑者在配置详情发起变更，填写原因与计划时间。
  2. 系统计算 Diff、影响面与风险等级，编辑者确认后提交。
  3. 审批人收到待办，查看 Diff 与影响面，通过或驳回。
  4. 审批通过后，发布者手动执行发布，或由定时任务到点执行。
  5. 平台写入 TongNCS、读回校验、记录发布记录与审计。
  6. 通知相关人，变更单进入已发布。

6.2 计划发布与发布窗口

  1. 提交变更单时可填写计划发布时间，用于审批排序与提醒；审批通过后也可直接设为"到点自动发布"。
  2. 定时任务到点执行前重新校验：审批仍有效、基线 MD5 一致、发布窗口允许、TongNCS 可用；任一不满足则转回"待发布"并告警，不自动重试。
  3. 发布窗口按环境配置，默认全天开放；窗口外不允许发布，定时任务同样受限。
  4. 不提供紧急发布通道；调整发布窗口只能由平台管理员操作，调整本身记录审计。

6.3 直连 TongNCS 变更检测

  1. 平台按固定周期（默认 5 分钟）拉取 TongNCS 配置变更历史 Assumption, TBD。
  2. 与平台发布记录按配置与时间比对。
  3. 发现无对应发布记录的变更，生成"未授权变更"审计事件。
  4. 立即报警：企业微信群机器人 + 站内通知，并在群内 @ 应用负责人；同时在配置详情打标。
  5. 支持人工"补录说明"，但报警记录与事件本身不可删除。

6.4 回滚与误删恢复

  1. 发布者从发布记录选择目标版本；回滚到上一已发布版本可直接执行并填写原因，回滚到更早版本需重新审批。
  2. 执行写 TongNCS 与读回校验，生成新的发布记录；原变更单标记已回滚并关联回滚记录。
  3. 删除类变更通过后执行软删除：从 TongNCS 删除，平台回收站保留完整内容 30 天。
  4. 恢复时把原内容重新写入 TongNCS，读回校验通过后标记已恢复；恢复生成新的发布记录与审计。
  5. 超过 30 天的回收站条目不可恢复。

6.5 发布失败与重试

发布失败后变更单进入"发布失败"，不自动重试，避免重复写入造成抖动。发布者需先核对 TongNCS 当前值：

  • 若目标值已生效：标记"实际成功"，补记发布记录，保留失败证据。
  • 若目标值未生效：可重新执行发布，沿用同一变更单与幂等键。
  • 若当前值被第三方改动：需重新创建变更单，基于新基线重新审批。
07

功能需求

P0 共 12 项。每项固定描述目的、触发、处理规则、结果与状态、权限、异常。

FR-01

配置目录与详情

P0
目的
让用户按"应用—环境"找到配置，而不是记忆 Namespace/Group/DataId 原始坐标，并在同一页面看到治理状态。
触发
用户进入平台选择应用与环境；或从通知、审计事件、变更单、发布记录跳转。
处理规则
  • 目录树为：应用 → 环境 → 配置分组 → 配置项；映射关系由平台维护，一个 TongNCS 配置只能归属一个应用与环境，冲突时阻断保存。
  • 详情页展示：当前生效内容（实时读取 TongNCS）、最近发布记录、订阅实例数与分布、进行中的变更单、最近审计事件。
  • 未纳入映射的 TongNCS 配置进入"未纳管"清单，按数量与存在时长提示管理员。
  • 敏感配置的值默认脱敏，只显示字段名与是否已设置。
结果与状态
配置标记为"已纳管 / 未纳管 / 已失效"。TongNCS 不可用时展示最后一次成功读取的快照，并明确标注"可能过期"。
权限
只读观察者及以上可查看目录与普通配置；敏感值需"查看敏感配置"权限，且每次查看需填写原因并记录审计。
异常
TongNCS 超时 → 降级为快照并标注时间；配置在 TongNCS 已被删除 → 标记"已失效"但保留历史与审计；映射缺失 → 提示补建映射。

FR-02

变更单与 Diff

P0
目的
把"改配置"从直接写 TongNCS 变成有原因、有差异、有基线、可审批的变更单。
触发
用户在配置详情点击"发起变更"；从模板创建；从其他环境复制内容（P1 支持一键同步）。
处理规则
  • 变更单必填：标题、变更原因、目标配置、变更类型（新增/修改/删除）、变更后内容、计划发布时间；风险等级由系统计算，用户只能上调不能下调。
  • 内容编辑保存为平台草稿，草稿不写入 TongNCS，也不影响运行时。
  • Diff 以行为单位展示新增、删除、未变；敏感字段两侧都脱敏。
  • 同一配置同一时刻只允许一个"进行中"变更单（草稿不占用）；存在进行中变更单时，其他人只能查看或申请协作。
  • 提交时记录 TongNCS 当前内容 MD5 作为基线；发布前再次校验，不一致则阻断并要求重新比对。
  • 删除类变更必须单独确认，并在影响面中列出订阅实例；删除为软删除，平台保留完整内容 30 天，可在回收站恢复，超过 30 天不可恢复。
结果与状态
草稿 → 待审批；生成变更单号。变更单内容与影响面以提交时快照为准，后续 TongNCS 变化不回写已提交快照。删除类变更发布后，配置进入"已删除（可恢复）"，同时出现在回收站。
权限
配置编辑者可创建与编辑自己的草稿；他人草稿只读；删除草稿仅本人或平台管理员；提交权限与编辑权限同域。
异常

FR-03

审批中心

P0
目的
让审批人在一个地方处理所有待办，并确保"提交的人不能自己批"。
触发
变更单提交；审批人打开待办。
处理规则
  • 待办按风险等级与等待时长排序；可批量浏览，但必须逐单决策。
  • 审批页面同时展示：变更单信息、完整 Diff、影响面、该配置历史发布与回滚记录、提交人。
  • 审批动作：通过、驳回（必须填理由）、转交（被转交人须具备审批权限）。
  • 生产环境强制"提交人 ≠ 审批人"，并强制"发布人 ≠ 审批人"；唯一例外：发布人是该应用的应用负责人。
  • 生产环境统一为单人会签：1 名审批人通过即可；高风险变更强制由应用负责人审批。
  • 审批通过后进入"已通过待发布"，持续有效，直到基线变化、变更单被取消或已发布；不设审批等待超时与自动驳回。
  • 审批期间基线变化：变更单退回"待审批"，已完成的审批意见保留但需重新确认。
结果与状态
待审批 → 审批中 → 已通过待发布 / 已驳回。全程写审计。
权限
审批人只能处理其授权应用与环境范围内的变更单；不能审批自己提交的单；高风险变更仅应用负责人可审批。
异常
无可用审批人 → 升级至应用负责人并告警；审批人离职或账号禁用 → 管理员可批量转交；不做审批超时判断，也不自动驳回。
FR-04

发布与灰度

P0
目的
在审批通过后，把内容安全写入 TongNCS，并让灰度过程可观察、可回退。
触发
发布者点击发布；到达计划发布时间（定时发布）；灰度观察期结束触发提示。
处理规则
  • 发布前预检：变更单处于"已通过待发布"、未因基线变化被打回、基线 MD5 一致、发布者有目标环境权限、TongNCS 连接可用、服务账号权限足够。
  • 通过 TongNCS 提供的配置发布能力写入；写入成功后立即读回并比对内容 MD5，不一致视为发布失败。
  • 灰度复用 TongNCS 的 Beta / Tag 能力；平台记录灰度方式、匹配条件、观察窗口、放量与转全量操作。
  • 灰度期间变更单保持"发布中（灰度）"；转全量并读回一致后才进入"已发布"。
  • 发布幂等：同一变更单 + 同一目标版本只允许一次有效写入；重复点击直接返回既有发布记录。
  • 计划发布时间可手动触发，也可设为到点自动发布；发布窗口按环境配置且默认全天，窗口外不允许发布；不提供紧急发布通道。
结果与状态
已通过待发布 → 发布中 → 已发布 / 发布失败；灰度中为发布中的子状态。生成发布记录（版本号、操作人、目标 MD5、读回结果、灰度范围）。
权限
发布者需目标环境发布权限；灰度放量与转全量同权限；发布窗口由平台管理员配置，调整记录审计。
异常
写入成功但读回失败 → 标记"结果不确定"，禁止自动重试，提示人工核对；部分实例未收到推送 → 展示订阅快照差异并告警；TongNCS 不可用 → 阻断发布；灰度无匹配实例 → 阻断转全量并提示检查匹配条件；窗口外发布 → 阻断并提示可用窗口。
FR-05

全量操作审计

P0
目的
覆盖"谁在何时对哪个对象做了什么、结果如何"，可检索、可导出、可举证，并能发现绕过平台的直连变更。
触发
任何写操作、审批、授权、导出、敏感值查看、连接配置修改、配置删除与恢复、直连检测事件自动记录；用户主动查询或导出。
处理规则
  • 审计范围：变更单创建/编辑/提交/审批/发布/回滚/取消、配置删除与恢复、权限授予与回收、账号创建与禁用、登录、敏感值查看、审计导出、TongNCS 连接与映射修改、直连变更检测。
  • 每条事件包含：事件 ID、时间、操作人、来源 IP、动作、对象、变更前后值（脱敏）、结果、TraceId、关联变更单、哈希。
  • 只追加，不支持编辑或删除；按日生成哈希链，导出文件附带校验值。
  • 审计事件永久保留，不自动删除、不允许单条或批量删除；仅支持按条件查询与导出。
  • 查询维度：时间范围、动作、应用、环境、操作人、结果、关键字；导出为异步任务。
  • 直连检测：定时比对 TongNCS 配置历史与平台发布记录，无对应记录的变更记为"未授权变更"，并立即报警到企业微信群与站内，同时通知应用负责人与审计员。
结果与状态
审计事件只增不改、永久保留；导出任务状态为生成中 / 可下载 / 失败 / 已过期。
权限
审计员与平台管理员可查看全部；普通用户仅查看与自己相关的审计；导出需"审计导出"权限。
异常
审计写入失败 → 阻断对应业务操作（审计优先）；导出数据过大 → 异步分片并限速；TongNCS 历史被清理导致比对缺口 → 标注"检测盲区"并提示缩短检测周期；企业微信报警发送失败 → 重试并降级站内，同时通知平台管理员。

FR-06

权限与授权

P0
目的
用"应用 × 环境"的业务语义授权，弥补 TongNCS 原生 RBAC 与组织职责之间的差距。
触发
管理员创建或禁用账号；管理员授权；人员入转调离；临时项目授权到期；应用负责人移交。
处理规则
  • P0 使用平台自建账号：管理员创建、密码策略、启用/禁用、离职冻结；SSO 接入需评估，列为 P1，不在 P0 上线。
  • 平台权限点：查看、编辑、提交、审批、发布、回滚、查看敏感值、查看审计、导出审计、平台管理。
  • 授权主体：用户或用户组；授权范围：应用 × 环境；支持角色模板（只读、编辑者、发布者、审批人、负责人）批量套用。
  • 平台权限与 TongNCS 服务账号权限需同时满足；调用 TongNCS 使用受控服务账号，不使用个人 TongNCS 凭证。
  • 支持临时授权与到期自动回收；回收权限不影响已发布配置，但立即阻断后续操作。
  • 职责分离作为硬约束：同一变更单提交人不得审批；发布人不得与审批人相同，唯一例外是发布人为该应用负责人。
结果与状态
授权状态：生效 / 已回收 / 已过期；账号状态：启用 / 禁用 / 已冻结。每次变更记录审计。
权限
平台管理员可创建、禁用账号并全局授权；应用负责人只能授权其负责应用范围内的角色（不可授予平台管理）。
异常
服务账号权限不足 → 发布预检直接报错并指出缺失动作；权限缓存异常 → 默认拒绝（fail-closed）；连续登录失败达到阈值 → 锁定账号；账号被禁用 → 立即阻断登录，名下未完成变更单需转交。
FR-07

影响面与风险提示

P0
目的
在提交、审批、发布前，让决策者知道"这次改动会影响谁、最坏会怎样"。
触发
变更单编辑、提交、审批、发布各环节自动计算并刷新展示。
处理规则
  • 影响面数据：订阅该配置的实例数、所属应用与负责人（来自 TongNCS 监听查询快照）；订阅实例可稳定映射到应用与负责人，映射结果同时作为通知对象。
  • 同分组关联配置与已维护的上游依赖纳入影响面 Assumption, TBD。
  • 风险因子：生产环境、敏感配置、删除操作、Diff 规模、影响实例数、该配置近期失败或回滚记录、非工作时间发布。
  • 风险等级为低 / 中 / 高，由规则加权得出；用户可上调不可下调；高风险变更强制由应用负责人单人会签。
  • 同时展示"发布失败会怎样"与"回滚路径是否可用"。
结果与状态
风险评估随变更单提交形成快照；快照不因后续 TongNCS 数据变化而改变，但详情页可显示"最新影响面"作为对照。
权限
可查看变更单的人均可看到风险结论；实例与依赖明细需配置查看权限。
异常
监听查询不可用 → 显示"未知"并自动把风险上调一级；订阅快照过期 → 标注采集时间；无订阅实例 → 提示"可能无人使用或采集异常"，需人工确认。
FR-08

回滚与删除恢复

P0
目的
在发布引发异常时快速恢复到已知良好版本；配置被误删时可在 30 天内恢复，并留下完整证据。
触发
发布后发现异常；配置被软删除后需要恢复；监控告警联动（P1）；用户主动回滚。
处理规则
  • 回滚目标：平台发布记录中的任意版本，或 TongNCS 历史版本。
  • 回滚到"上一已发布版本"：发布者可直接执行，必须填写原因，事后审计 Assumption, TBD。
  • 回滚到更早版本：创建回滚变更单，重新走审批。
  • 回滚同样执行写入 TongNCS + 读回校验；生成新的发布记录，不覆盖原记录。
  • 删除的配置进入回收站保留 30 天；恢复时把原内容重新写入 TongNCS 并读回校验，生成新的发布记录与审计。
  • 恢复需发布权限；若同名配置已存在，必须选择覆盖（重新走审批）或放弃恢复，不允许静默覆盖。
  • 原变更单标记"已回滚"并关联回滚记录；回滚与恢复本身也进入审计。
结果与状态
已回滚 / 已恢复；回收站条目状态：可恢复 / 已过期。失败时保持原状态并高优告警，不允许静默失败。
权限
回滚与恢复权限独立于编辑权限；生产操作需发布权限；跨应用回滚不允许。
异常
目标版本内容已不存在 → 阻断并提示选择其他版本；超过 30 天 → 不可恢复；恢复时同名冲突 → 阻断并提示；回滚后订阅未更新 → 告警并展示实例差异；TongNCS 不可用 → 阻断并保留待执行意图，恢复后需人工确认再执行。
FR-09

通知与集成

P0
目的
让相关人在正确的时间收到正确的事件，同时保证通知失败不影响主流程。
触发
变更单提交、审批、发布、发布失败、回滚、定时任务执行结果、直连告警。
处理规则
  • P0 渠道：站内通知 + 企业微信群机器人（Webhook）；邮件与其他 IM 渠道列入 P1。
  • 按应用与环境绑定企业微信群；直连变更报警、发布失败、定时任务失败在群内 @ 应用负责人。
  • 通知内容包含对象、动作、结果、操作人、跳转链接；不包含敏感配置明文。
  • 发送失败进入重试队列，最多 3 次；最终失败记录审计但不阻塞业务。
  • 同一对象短时间内的多次事件按窗口聚合，避免通知风暴。
结果与状态
通知状态：待发送 / 已发送 / 失败 / 已聚合。
权限
用户管理自己的通知偏好；平台管理员配置全局渠道与默认订阅。
异常
企业微信机器人不可达或被限流 → 重试 3 次后降级站内，并通知平台管理员；机器人密钥失效 → 阻断保存并提示更新；通知模板缺少变量 → 阻断保存模板。
FR-10

平台设置与 TongNCS 连接

P0
目的
让平台安全接入现有 TongNCS 的多环境实例，并可控地维护配置映射。
触发
初次部署；新增环境或 TongNCS 实例；连接异常；映射调整。
处理规则
  • 环境与实例一一绑定：dev / staging / prod 各自使用独立 TongNCS 实例，不允许跨环境复用同一实例；命名空间在该实例内隔离。
  • 录入 TongNCS 地址、命名空间、认证方式；凭证加密存储，界面不回显，仅允许覆盖更新。
  • 连接测试：读取目标命名空间的配置列表与一条样例配置，验证连通性与读写权限。
  • 维护映射：应用 / 环境 / 逻辑配置名 ↔ 命名空间 / 分组 / 数据 ID；支持批量导入与冲突检测。
  • 健康检查：定时探活；连续失败标记"不可用"，并联动阻断发布。
  • 平台治理数据独立持久化，但配置生效值仍以 TongNCS 为唯一来源。
结果与状态
连接状态：已连接 / 降级 / 不可用；映射状态：生效 / 冲突 / 未映射。
权限
仅平台管理员可维护连接与映射；操作全部审计。
异常
凭证失效 → 告警并阻断发布；一个 TongNCS 配置被映射到多个应用 → 阻断保存；环境未绑定实例 → 阻断该环境的发布；连接恢复后不自动补发，需人工确认。
FR-11

多环境对比与受控同步

P0
目的
让同一配置在 dev / staging / prod 之间可比较、可按审批流程同步，减少手工复制造成的环境漂移。
触发
用户在配置详情选择"环境对比"；或选择"同步到其他环境"。
处理规则
  • 对比以"逻辑配置"为锚点，分别读取各环境 TongNCS 实例的当前内容；对比过程只读，不写任何环境。
  • 差异按行展示"仅源环境存在 / 仅目标环境存在 / 内容不同"；敏感值在对比结果中同样脱敏。
  • 同步是单向受控动作：以源环境内容生成目标环境的变更单，预填差异说明，必须走目标环境的审批与发布，不直接写目标 TongNCS。
  • 支持同步整份内容或选中的键；目标环境已存在进行中的变更单时阻断，避免并发覆盖。
  • 跨环境映射缺失时提示先完成配置映射；格式不一致（如 YAML 与 Properties）时阻断同步。
结果与状态
对比结果生成只读快照并可分享；同步生成目标环境变更单，并记录源环境、源版本与关联变更单。
权限
查看对比需目标环境查看权限；发起同步需目标环境编辑权限；发布仍需目标环境发布权限。
异常
任一环境不可用 → 标注该环境并禁止同步；三方内容均不同 → 要求人工逐项确认；源配置已被删除或未纳管 → 阻断并提示。
FR-12

定时发布与批量变更单

P0
目的
支持计划内自动发布与一次处理多个配置，减少重复操作，同时保持逐项审批与逐项校验。
触发
审批通过后设置"到点自动发布"；用户一次选择多个配置发起批量变更。
处理规则
  • 定时发布：审批通过后设定执行时间；到点前可取消或改期，改期不重新审批，修改内容必须重新审批。
  • 到点执行前重新校验审批状态、基线 MD5、发布窗口、TongNCS 可用性与服务账号权限；任一不满足则转回"待发布"并告警，不自动重试。
  • 定时任务由系统账号代执行，审计同时记录系统账号与原发布人；发布记录仍归属原发布人。
  • 批量变更单由父单与子项组成：每个子项独立 Diff、独立影响面；审批按子项最高风险执行，高风险子项由应用负责人审批。
  • 批量发布逐项执行，允许部分成功；父单聚合展示成功、失败、未执行，可对失败子项单独重试。
  • 单次批量上限默认 50 个配置 Assumption, TBD。
结果与状态
定时任务：待执行 / 执行中 / 已执行 / 已取消 / 执行失败；批量单：待审批 / 部分通过 / 已通过 / 部分成功 / 已发布 / 已失败。
权限
定时发布需目标环境发布权限；批量变更需目标环境编辑权限，发布时逐项校验发布权限。
异常
到点 TongNCS 不可用 → 任务失败并告警，不自动补发；批量部分失败 → 父单标记"部分成功"，未成功项可单独重试；审批已失效 → 不执行并通知提交人；批量中存在无权限配置 → 整单阻断并列出。
08

共享规则

以下规则在多个功能中生效，只在此处定义一次。

规则定义
TongNCS 唯一事实源生效配置只存在于 TongNCS。平台草稿、快照、Diff 均不是运行时来源。任何"发布成功"必须经过写入 TongNCS 并读回校验。
四眼原则与单人会签生产环境提交人不得审批自己的变更单；生产审批为单人会签，1 名审批人通过即可；高风险变更强制由应用负责人审批；发布人不得与审批人相同，唯一例外是发布人为该应用负责人。
审计优先审计只追加、不可修改或删除；按日哈希链；审计写入失败时，对应业务操作失败，不允许"无审计的成功"。
敏感数据保护敏感值默认脱敏；查看明文需单独权限 + 填写原因 + 记录审计；通知、导出、Diff 默认不含明文。
并发与幂等同一配置同一时刻仅一个进行中变更单；发布使用"变更单号 + 目标版本"作为幂等键；提交与发布前均校验基线 MD5。
权限即时生效授权变更实时生效；权限判断失败时默认拒绝；平台权限与 TongNCS 服务账号权限需同时满足。
账号与身份源P0 使用平台自建账号，账号由管理员创建与禁用；SSO 接入需评估，列为 P1；账号禁用后立即阻断登录，历史审计保留。
通知非阻塞通知失败不影响变更、审批、发布的主流程，仅记录与重试；P0 通知渠道为站内 + 企业微信群机器人。
状态一致性变更单、审批任务、发布记录、审计事件通过变更单号关联；任何状态变化必须同时写审计；不允许手工改状态。
软删除与恢复配置删除为软删除，平台保留完整内容 30 天；恢复需发布权限并重新写入 TongNCS、读回校验；超过 30 天不可恢复。
降级只读TongNCS 不可用时平台进入只读：可查看最后快照、可编辑草稿，但禁止发布、回滚、恢复与灰度。
时间参数审计永久保留；审批通过后持续有效，不设审批等待超时与自动驳回；直连检测周期 5 分钟；灰度默认观察窗口 30 分钟；软删除保留 30 天；发布窗口默认全天。审计保留与审批超时规则为已确认规则，其余为默认值 Assumption, TBD。
09

异常与边界

集中列出必须定义行为的关键场景，避免实现时各自发挥。

场景产品行为
TongNCS 不可用展示最后一次成功快照并标注"可能过期"；阻断发布、回滚、灰度；允许编辑与保存草稿；恢复后不自动执行任何写操作。
审批期间基线变更变更单退回待审批；通知提交人与已审批人；要求重新比对三方 Diff 后再次提交。
审批无人处理不做超时判断、不自动驳回；仅在待办列表与站内消息中持续提示，必要时由管理员转交应用负责人。
发布超时 / 结果不确定不自动重试；标记"结果不确定"；要求人工读取 TongNCS 当前值后选择"补记成功"或"重新发布"。
灰度无匹配实例阻断转全量；提示检查标签与匹配条件；记录一次失败的灰度尝试。
定时任务到点校验失败不执行发布，转回"待发布"并告警；不自动重试，需人工确认后重新设定或手动发布。
批量发布部分成功父单标记"部分成功"；逐项展示成功与失败原因；失败子项可单独重试，不重发已成功项。
跨环境对比时某环境不可用标注该环境为"不可读"，其余环境仍可对比；禁止向不可读环境发起同步。
回滚目标不存在阻断回滚并提示选择其他版本；不允许以"空内容"回滚。
删除仍有订阅的配置影响面明确列出实例数；删除类变更强制高风险；需负责人确认；删除后进入回收站保留 30 天。
恢复已删除配置仅 30 天内可恢复；恢复需发布权限并重新写入 TongNCS、读回校验；同名配置已存在时需选择覆盖（重新审批）或放弃。
软删除超过 30 天不可恢复；配置从回收站移除，保留删除审计事件。
账号被禁用立即阻断登录与所有写操作；名下未完成变更单转交应用负责人；历史审计与操作记录保留。
企业微信群机器人不可用重试 3 次后降级站内通知，并通知平台管理员；直连报警不可因此丢失，需在站内保留告警。
权限被回收立即阻断后续操作；不影响已发布配置；进行中的变更单转交或取消。
导出数据过大转异步任务并分片生成；设置单次导出上限；失败可重试，导出行为本身写审计。
并发提交同一配置后提交者被阻断，提示已存在进行中变更单；可申请协作或等待关闭。
空状态无应用、无配置、无待办、无审计时，分别给出下一步操作指引，不显示空白页。
直连变更无法比对TongNCS 历史清理导致缺口时，标注"检测盲区"；建议缩短检测周期或调整保留策略。

效率与一致性

术语表

术语定义
变更单一次受控配置变更的载体，包含原因、内容、Diff、影响面、审批与发布结果。
发布把变更单的目标内容写入 TongNCS 并读回校验成功的动作。
灰度只让部分实例先收到新配置的发布方式，复用 TongNCS 的 Beta / Tag 能力。
直连变更绕过平台、直接在 TongNCS 控制台或 API 修改配置的行为。
基线与基线 MD5提交变更单时 TongNCS 当前内容的摘要，用于发布前确认没有被他人改动。
影响面本次变更会波及的实例、应用与依赖范围。
敏感配置包含口令、密钥、连接串等需要脱敏与单独授权查看的配置。
四眼原则关键操作至少由两个人分别完成，避免单人独断；在本产品中体现为提交人与审批人分离。
单人会签生产变更只需 1 名审批人通过即可进入待发布；该审批人不得是提交人。
软删除 / 回收站删除后配置从运行时移除，平台保留完整内容 30 天；期间可恢复，超过 30 天不可恢复。
定时发布审批通过后设定执行时间，由系统到点校验并自动完成发布；失败不自动重试。
批量变更单包含多个子项的一次变更，父单聚合审批与发布结果，子项独立 Diff 与重试。
多环境受控同步以源环境内容生成目标环境变更单，经目标环境审批与发布后生效，不直接写目标环境。
未纳管配置存在于 TongNCS 但尚未建立应用/环境映射的配置。
审计哈希链按日把审计事件串联计算摘要，用于证明记录未被篡改。
