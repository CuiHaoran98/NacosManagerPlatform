# TongNCS 配置治理平台详细设计方案编写计划

## 1 摘要

- **目标**：在现有 PRD、架构稿与规格基础上，产出一份可直接指导 Java / Spring Boot 实现的详细设计方案，不写任何代码。
- **交付物**：`/workspace/tongncs-config-governance-detailed-design.md`（Markdown，单一文件）。
- **输入**：`nacos-config-governance-prd.html`（PRD v1.1）、`tongncs-config-governance-architecture.html`、`.trae/specs/formalize-governance-rules-and-acceptance/spec.md`（v1.3）、`rule.md`、`agent.md`、`static-acceptance-report.md`。
- **不在本次范围**：Java 代码、脚手架、数据库迁移脚本、接口实现、前端页面、TongNCS 真实联调。

## 2 现状分析

- `/workspace` 目前是**纯文档仓库**：没有 `package.json`、`pom.xml`、`go.mod`，没有测试目录、SQL 或迁移文件。
- 已具备的设计输入：
  - PRD：FR-01 ~ FR-12、7 类角色、16 项决策、P0 非目标。
  - 架构稿：12 个模块、模块化单体、无状态 Web + 单活 Worker + 元数据库、适配器五方法与 `verified / rejected / indeterminate` 三态。
  - 规格：16 条 Requirement、33 个 Scenario、81 条规则、20 条架构约束、26 个 AC、37 条错误码、12 类对象字段、6 组状态机。
- 尚缺、需要本设计补齐的内容：
  - Java / Spring Boot 工程结构与包边界；
  - PostgreSQL 表结构、索引、唯一约束、乐观锁字段；
  - REST API 清单、请求/响应结构、错误码到 HTTP 的映射；
  - 发布、回滚、恢复、同步、定时、批量的时序与事务边界；
  - 适配器真实实现约束（超时、认证、读回、故障注入）；
  - 部署参数、密钥管理、可观测性与测试策略。
- 必须持续遵守的硬约束：TongNCS 唯一事实源；Release 唯一写入口；状态与审计同事务；`indeterminate` 禁止自动重试；P0 不引入消息中间件、不拆微服务。

## 3 技术基线（本设计固定）

| 项 | 选择 | 说明 |
|---|---|---|
| 语言 | Java 21 LTS | 使用 record、sealed、虚拟线程需评估后再定 |
| 框架 | Spring Boot 3.3.x | Spring MVC + Spring Security + Validation |
| 构建 | Maven | 单模块起步，按包边界分层，不拆多模块工程 |
| 数据库 | PostgreSQL 16 | 单库单 schema `ncg`，表按模块前缀，禁止跨模块 JOIN |
| 迁移 | Flyway | 设计文档只给 DDL 设计，不生成迁移文件 |
| 数据访问 | Spring Data JDBC | 显式 SQL 友好，避免隐式懒加载跨模块读表 |
| 会话 | Spring Security + 服务端 Session | 自建账号，P0 不接入 SSO |
| HTTP 客户端 | Spring RestClient | 统一超时、错误映射、TraceId 透传 |
| 调度 | Spring `@Scheduled` + 数据库租约 | 单活 Worker + 热备，不引入 Quartz 集群 |
| 测试 | JUnit 5 + Testcontainers + WireMock + MockMvc | 适配器契约测试同时跑假件与沙箱 |
| 可观测 | Micrometer + Logback JSON + MDC TraceId | 指标、结构化日志、告警埋点 |
| 前端 | Vue 3 + Vite + TypeScript | 仅作为假设列出；本设计不展开页面细节 |

> 上述选型作为设计基线；如团队已有强制标准，只需替换本节并在文档中记录差异，不影响章节结构。

## 5 编写阶段

### D0 资料对齐与术语冻结

- 通读 PRD、架构稿、spec、rule.md、agent.md、静态报告。
- 输出术语表：模块、接口、接缝、适配器、发布、变更单、实例、映射、治理元数据。
- 完成标准：术语与 `codebase-design` 用词一致，不出现“组件/服务/边界”等替代词。

### D1 架构与技术基线

- 写第 1~3 章：不变量、部署拓扑、模块依赖、Maven 与包结构。
- 明确 12 个模块的包名与允许依赖，给出禁止依赖清单。
- 完成标准：唯一写入口、模块不跨表、Web/Worker 职责清晰。

### D2 领域模型与数据库

- 写第 4~5 章：12 类对象、6 组状态机、表结构与索引。
- 每张表必须写：主键、非空、唯一约束、外键、`version`、时间字段、脱敏字段。
- 完成标准：状态迁移与 spec E.2 一一对应；发布、建单、直连检测、通知四类唯一约束齐全。

### D3 接口与核心流程

- 写第 6~8 章：REST 清单、错误封装、幂等键、10 条核心时序。
- 每个流程必须标注事务边界：哪些写库同事务、外部调用在事务外、结果如何回写。
- 完成标准：AC-01 ~ AC-26 都能落到至少一个接口或流程；37 条错误码全部有 HTTP 映射。

### D4 横切能力与部署

- 写第 9~17 章：权限、审计、通知、Worker、失败模型、安全、可观测、测试、部署。
- 完成标准：审计哈希链可验证；通知失败不回滚业务；实例不可用进入只读；部署参数可执行。

### D5 验收映射与自检

- 写第 18~19 章：FR/AC 映射表、未决项清单。
- 执行一致性自检：编号、计数、状态机、错误码、TBD 标注。
- 完成标准：无孤儿 AC；无未标注的未知值；文档可交给 Java 开发者直接拆分任务。

## 6 关键设计决策（文档中必须明确写出）

1. **包结构**：`com.<org>.ncg.{catalog,change,approval,release,audit,impact,envsync,scheduler,batch,notification,auth,adapter,shared}`；模块间只经应用接口调用。
2. **数据库**：单库单 schema，表名按模块前缀；禁止跨模块 JOIN，查询类跨模块需求走应用层组装或只读视图。
3. **主键**：沿用 spec 的 ULID，存 `varchar(26)`；时间字段统一 UTC。
4. **发布事务**：先提交“发布意图”记录，再在事务外调用 TongNCS，最后用新事务写“发布结果”；不允许长事务包外部调用。
5. **幂等**：`release_key = change_no + ':' + target_version` 唯一索引；Worker 任务以同一键重放时返回既有结果。
6. **审计**：按日 `seq` + `prev_hash/event_hash`；SHA-256 规范化 JSON；数据库账号无 UPDATE/DELETE 权限。
7. **适配器**：`TongNCSConfigPort` 五方法；`publish` 只做一次写尝试并读回，不自动重试；超时映射为 `indeterminate`。
8. **权限**：Spring Security 会话认证 + 方法级权限校验；权限判断异常一律拒绝。
9. **敏感值**：AES-256-GCM 应用层加密，密钥来自环境变量/密钥文件，密文带 key id；日志与通知统一脱敏器。
10. **通知**：发件箱表 + 轮询发送；企微机器人失败重试 3 次，最终失败只写审计。
11. **调度**：单活 Worker 通过数据库租约抢占任务；租约过期可接管；到点复核失败不自动补发。
12. **API 风格**：`/api/v1/...`，统一错误体 `{code, message, traceId, details}`；列表分页 `page/size`。
13. **前端**：Vue 3 + TypeScript 仅作假设，设计文档只定义接口契约与页面所需字段，不展开组件设计。
